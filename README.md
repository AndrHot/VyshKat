# ВышКат — учёт парка кикшеринга

C# / .NET 8, `Microsoft.Extensions.DependencyInjection`, xUnit.

## Запуск

```bash
dotnet run --project src/VyshKat              # меню
dotnet run --project src/VyshKat -- --demo    # демо всех сценариев
dotnet test                                   # тесты
```

## Устройство

- `Asset` — всё, что стоит на балансе (имя + инвентарный номер). От него наследуются:
  - транспорт `Vehicle`: `Scooter`, `Bicycle`, `ElectricBicycle` — у них есть простота (1–10) и техсостояние (%);
  - вещи `Equipment`: `Helmet`, `DockStation`, `ChargingCabinet`.
- `IEnergyConsumer` — те, кто тратит энергию (самокат, электровелосипед, док-станция, шкаф). Велосипед и шлем его не реализуют.
- `Fleet` — список всего на балансе, выдаёт номера `VK-0001`, `VK-0002`…
- `FleetService` — транспорт принимает только после техосмотра (`IServiceCenter`), вещи ставит сразу.
- `ServiceCenter` — пропускает транспорт с техсостоянием от 60 %.
- `SimplicityBeginnerPolicy` — транспорт подходит новичкам при простоте от 6.
- `FleetReports` — количество, суммарная энергия, список для новичков, инвентарный список.
- `ConsoleUi` — меню и демо. Зависимости собираются в `AddVyshKat()`.

## SOLID

- **S** — каждый класс делает одно: `FleetService` принимает, `FleetReports` считает, `ConsoleUi` общается с пользователем.
- **O** — новый вид транспорта — это новый класс-наследник, сервисы и отчёты не меняются.
- **L** — любой наследник `Vehicle` подходит туда, где ждут `Vehicle`.
- **I** — маленькие интерфейсы `IEnergyConsumer` и `IInventoried`: велосипеду не нужно делать вид, что он тратит энергию.
- **D** — сервисы зависят от интерфейсов `IServiceCenter` и `IBeginnerPolicy`, реализации подставляет DI-контейнер.

## Ответы на вопросы

**Какой принцип применён наиболее явно?**
Открытость/закрытость (O) в иерархии `Asset`: чтобы добавить сегвей, достаточно класса `Segway : Vehicle, IEnergyConsumer` и одной строки в меню.

**Какой принцип сознательно ограничен?**
Инверсия зависимостей (D). У `Fleet`, `FleetService` и `FleetReports` нет интерфейсов — у них одна реализация, интерфейсы были бы лишними. Интерфейсы есть только у техосмотра и правила для новичков, которые реально могут поменяться.

**Что будет при расширении?**
- Новый транспорт или вещь — новый класс и строка в меню, остальное не трогается.
- Сотрудник — это не `Asset`, поэтому в учёт не попадёт; для него будет свой класс и сервис.
- Склад запчастей — запчасть можно сделать наследником `Equipment`, остатки вести отдельным сервисом.

**Какие тесты проверяют техосмотр и правило для новичков?**
В `ServicesTests`: `ServiceCenter_AcceptsFromSixtyPercent` (граница 59/60 %) и `BeginnerPolicy_RequiresSimplicityAtLeastSix` (граница 5/6).
Техосмотр подменяется через DI: в контейнер поверх обычных регистраций кладётся `FakeServiceCenter`:

```csharp
new ServiceCollection().AddVyshKat().AddSingleton<IServiceCenter>(fake).BuildServiceProvider();
```

Тесты `AcceptVehicle_...` проверяют, что решение принимает именно fake: если он одобрил, самокат с техсостоянием 10 % попадает в парк, если отказал — не попадает.

**Что сделал ИИ, а что вы?**
Первую версию кода, тестов и README сгенерировал ИИ (Claude). Она получилась слишком громоздкой (±1050 строк кода, 33 теста, README на 143 строки). Было стратегически вырезано:
- отчёт с разбивкой по видам техники (оставил всего / транспорт / вещи);
- таблицы видов транспорта с лямбдами в меню — заменил на обычный `switch`;
- отдельные `Guard`, `AcceptanceResult`, фабричные методы `InspectionResult.Accept/Reject`;
- отдельный счётчик инвентарных номеров (номер берётся из размера парка);
- собственное исключение для конца ввода (используется `EndOfStreamException`);
- XML-комментарии во всём коде;
- дублирующие тесты (33 → 17) и половина README.

При проверке ещё было исправлено:
- тест отчёта по видам падал: массив кортежей сравнивался со списком;
- отрицательный расход энергии проверялся через обобщённый `CheckRange` с `decimal.MaxValue` — заменил на простой `CheckEnergy`;
- тест «велосипед не потребляет энергию» через `is` давал предупреждение компилятора «всегда false» — переписал через `typeof`.

**Ограничения:** парк хранится только в памяти; техосмотр смотрит только на техсостояние, правило для новичков — только на простоту; технику нельзя списать; сотрудников и склада запчастей нет.
